# Release 0.2.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unreleased の 10 件を 0.2.2 としてリリースする（Cargo.toml / CHANGELOG / README の 3 点同期と検証、タグ打ち）

**Architecture:** 3 ファイルの同期を 1 コミットにまとめ、Nix flake が Cargo.toml の version を読むことを `nix-instantiate --parse` と `nix build` で検証してからタグを打つ。`cargo fmt/check/clippy/test` と両 smoke はリリースコミット前に必須。

**Tech Stack:** Rust 2021 / Cargo / Nix flake / GitHub Actions release.yml

**Spec:** `CHANGELOG.md:5` の Unreleased 10 行と `AGENTS.md` の「Changelog and release」節（version は Cargo.toml 単一管理、CHANGELOG 見出し、README pin、flake 検証、タグ vX.Y.Z で release.yml がバイナリを配布）が権威。

## Global Constraints

- コメントは英語、plan は日本語
- `cargo fmt && cargo check --all-targets && cargo clippy --all-targets -- -D warnings && cargo test` が全て green（AGENTS.md の pre-commit gate）
- `init` は DB/data dir に触れない（既存テストで担保）
- `flake.nix:13` は `builtins.fromTOML (builtins.readFile ./Cargo.toml)` で version を読む — Cargo.toml 以外で version を持たないこと
- コミット前にユーザー承認を得ること（AGENTS.md の Commits 節）
- タグは `v0.2.2`、リモートへの push は明示的承認後にのみ行うこと

### Task 2: 検証（flake パース / ビルド / pre-commit gate / smoke）

**Files:**
- 変更なし（検証のみ）。`Cargo.lock` が更新された場合は追加コミットなしで同リリースコミットに含める（`cargo check` 後の `git diff --stat` で確認）

**Interfaces:**
- Consumes: Task 1 のコミット（`0.2.2` に同期した 3 ファイル）
- Produces: 全 gate が green であることの証跡

- [ ] **Step 1: flake の構文検証（高速、fetch なし）**

  Run: `nix-instantiate --parse flake.nix`
  Expected: パース成功（何も出力せず exit 0）。`flake.nix:13` が `Cargo.toml` の `0.2.2` を正しく読めることを確認。

- [ ] **Step 2: flake ビルド**

  Run: `nix build .#default`
  Expected: `result/bin/seasalt` が生成され、`result/bin/seasalt --version` が `0.2.2` を返す。

  ```bash
  result/bin/seasalt --version
  # expected: seasalt 0.2.2
  ```

- [ ] **Step 3: pre-commit gate**

  Run: `cargo fmt && cargo check --all-targets && cargo clippy --all-targets -- -D warnings && cargo test`
  Expected: 全て green。`Cargo.lock` が更新されたら `git diff --stat` で確認し、更新があれば `git add Cargo.lock && git commit --amend --no-edit` でリリースコミットに含める（`shlex` 追加後の lock は既にコミット済みだが、version bump で再生成される可能性があるため）。

- [ ] **Step 4: smoke（bash, zsh）**

  Run: `cargo build --release && bash tests/bash/smoke.sh target/release/seasalt && bash tests/zsh/smoke.sh target/release/seasalt`
  Expected: 両方 `OK`（zsh が無い環境では `SKIP`）

- [ ] **Step 5: 最終差分確認**

  Run: `git log --oneline -2` / `git diff HEAD~1 --stat`
  Expected: 直前のリリースコミット `0adba3c` ではなく `chore(release): 0.2.2` が 1 コミットとして積まれ、`Cargo.toml`, `CHANGELOG.md`, `README.md`（と必要なら `Cargo.lock`）のみ。

### Task 3: タグ打ちと push（手動承認が必要な不可逆操作）

**Files:**
- 変更なし（Git タグのみ）

**Interfaces:**
- Consumes: Task 2 で検証済みの `chore(release): 0.2.2` コミット
- Produces: `v0.2.2` タグと GitHub Release（`release.yml` がバイナリを配布）

- [ ] **Step 1: タグを打つ（ローカルのみ）**

  Run: `git tag v0.2.2`
  Expected: `git tag --list | grep v0.2.2` で存在。

  タグメッセージは不要（軽量タグで `release.yml:4` の `push: tags: ["v*"]` がトリガー）。

- [ ] **Step 2: リモートへの push 前にユーザー承認を得る**

  説明: `git push origin main && git push origin v0.2.2` は不可逆（force ではないが公開される）ため、必ず承認を得てから実行する。`AGENTS.md` の「Destructive / Irreversible Actions」節に従う。

  Run（承認後にのみ）:

  ```bash
  git push origin main
  git push origin v0.2.2
  ```

  Expected: GitHub Actions の `release.yml` が `v0.2.2` で走り、`seasalt-x86_64-unknown-linux-musl.tar.gz` と `sha256SUMS` がリリースに添付される。`CHANGELOG.md:5` の `## [0.2.2] - 2026-08-22` 節がリリースノート本文に使われる。

- [ ] **Step 3: 事後確認**

  Run: `gh release view v0.2.2 --json tagName,body --jq .tagName`（`gh` が無い場合はブラウザで `https://github.com/miyakogi/seasalt/releases/tag/v0.2.2` を確認）
  Expected: タグ `v0.2.2` のリリースが存在し、本文が `CHANGELOG.md` の 0.2.2 節と一致。
