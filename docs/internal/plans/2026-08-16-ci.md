> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions で AGENTS.md の pre-commit ゲート + smoke テスト + flake ビルドを自動実行する。

**Architecture:** Nix ベース。`flake.lock` でピンされた dev シェル（devShells.default）を CI でも使用し、ローカルとツールチェーンを完全一致させる。製品コードの変更なし。ランナーは ubuntu-latest のみ（macOS は CI 分 10 倍・coreutils 追加が必要なため見送り、後から拡張可能）。bench は CI では実行しない（`cargo check --all-targets` でコンパイル検証のみ）。

**Tech Stack:** GitHub Actions, Nix (flake), Rust toolchain via nixpkgs pin

**Spec:** なし（bounded なインフラ設定タスク。設計は本プランが担う）

### Task 1: GitHub Actions ワークフロー作成

**Files:**
- Create: `.github/workflows/ci.yml`
- Modify: `AGENTS.md`（Commands に 1 行追加）

- [ ] **Step 1: ci.yml を作成** — `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  # The AGENTS.md pre-commit gate plus the shell integration smoke
  # test, run inside the pinned Nix dev shell so CI matches local
  # development exactly.
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: cachix/install-nix-action@v27
      - name: Pre-commit gate
        run: nix develop -c bash -c 'cargo fmt --check && cargo check --all-targets && cargo clippy --all-targets -- -D warnings && cargo test'
      - name: Shell integration smoke test
        run: nix develop -c bash -c 'cargo build --release && bash tests/bash/smoke.sh target/release/seasalt'

  # Verifies the flake package itself builds (a separate path from
  # building with cargo directly).
  nix-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: cachix/install-nix-action@v27
      - name: Build the package via the flake
        run: nix build .#default
```

## 設計判断と代替案（記録・2026-08-16）

ブレスト時にユーザーと決定した判断の記録。各判断につき「選んだ理由 / 棄却した代替案 / 誤りの場合のコスト」を残す。

### 1. ランナー戦略: Nix ベースを採用

- **選んだ理由:** ツールチェーン（cargo/rustc/rustfmt/clippy）を flake.lock でピンされた dev シェルと同一にできる。ローカルと CI のドリフトが構造的に起きない。`nix build .#default` ジョブで flake 自体のビルド検証も兼ねる
- **棄却した代替案:** 通常の rust ツールチェーン action（dtolnay/rust-toolchain）。セットアップは速いが、ツールチェーン版数を別途管理する必要があり dev シェルとずれ得る
- **誤りの場合のコスト:** ランナー上の Nix インストールに数十秒余分に掛かる

### 2. OS マトリクス: ubuntu のみ

- **選んだ理由:** README は macOS 対応を謳うが、macOS ランナーは CI 分が 10 倍課金される。また smoke テストは GNU coreutils の `timeout` を使うため、devShell に coreutils/bash を追加する必要があり、スコープが膨らむ。後から拡張可能
- **棄却した代替案:** ubuntu + macOS のマトリクス
- **誤りの場合のコスト:** macOS 固有のリグレッション（パス処理・coreutils 非依存化など）は CI では検出できず、ローカル検証のみになる

### 3. cargo bench: CI では実行しない

- **選んだ理由:** ベンチは実行環境のノイズを受けやすく、CI で閾値判定しない限り価値が薄い。`cargo check --all-targets` で benches のコンパイルは常に検証される
- **棄却した代替案:** criterion の quick モードで完走確認のみ行う
- **誤りの場合のコスト:** ベンチの実行時破損（panic や非決定的挙動）はローカル実行でのみ検出される

### 4. キャッシュ設定: 初期版では入れない

- **選んだ理由:** プロジェクトが小さく、依存も少ないためビルド時間が許容範囲。YAGNI
- **棄却した代替案:** Swatinem/rust-cache 等によるキャッシュ
- **誤りの場合のコスト:** 各ジョブのビルド時間が長めになる（遅くなったら追加する方針を Global Constraints に明記済み）
